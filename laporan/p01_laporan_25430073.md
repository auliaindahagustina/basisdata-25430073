## 1. Tujuan Praktikum
- Praktikum ini bertujuan untuk memahami penerapan MariaDB dalam manajemen basis data, dimulai dari pemeriksaan lingkungan hingga penataan akun dan hak akses pengguna. Di samping itu, praktik dilakukan untuk memahami pemanfaatan phpMyAdmin serta mengaplikasikan Git dalam penyimpanan dan pengelolaan file proyek basis data.

## 2. Ringkasan Dasar Teori
- Basis data berfungsi untuk menyimpan dan mengatur data secara terstruktur agar dapat digunakan kembali sesuai dengan kebutuhan. Pengelolaan dilakukan dengan menggunakan DBMS, salah satunya yaitu MariaDB yang diterapkan dalam praktikum ini. MariaDB beroperasi dengan model klien-server, sehingga perintah dari aplikasi seperti CLI atau phpMyAdmin disampaikan kepada server untuk diproses.
XAMPP membantu menciptakan lingkungan latihan dengan MariaDB dan phpMyAdmin. CLI berfungsi untuk mengeksekusi perintah SQL secara langsung, sedangkan phpMyAdmin menawarkan metode pengelolaan melalui antarmuka web. Perhatian terhadap penggunaan akun sangat penting karena setiap pengguna mungkin memiliki tingkat akses yang berbeda-beda. Pemberian hak yang memadai membantu membatasi akses ke basis data.
Selain manajemen basis data, Git digunakan untuk merekam perubahan pada file proyek melalui commit. Dengan cara ini, proses pengerjaan dapat disimpan secara bertahap dan kemajuan proyek lebih mudah dipantau.

## 4. Jawaban Titik Analisis

**Analisis 1**
- Perbedaan tersebut perlu diperhatikan saat mencari solusi di internet karena MySQL dan MariaDB memang punya perbedaan dalam fitur, sintaks, dan cara kerja. Dokumentasi MySQL masih bisa dipakai untuk konsep SQL yang sama atau yang kompatibel. Tapi kalau masalahnya terkait fitur khusus atau perilaku tertentu dari MariaDB, lebih baik cari di dokumentasi MariaDB. Dengan begitu, solusi yang ditemukan pasti cocok dengan sistem yang sedang digunakan.

**Analisis 2**
- Perintah mysql -u root tidak dapat diakses karena setelah password root diatur, masuk memerlukan password. Perintah itu tidak menggunakan opsi -p, sehingga kata sandi tidak diminta atau dikirim selama proses masuk. Pada pesan kesalahan, bagian using password: NO menunjukkan bahwa tidak ada kata sandi yang dikirim.

**Analisis 3**
- information_schema masih dapat diakses karena database itu berfungsi untuk menyajikan informasi atau metadata terkait server dan objek database. Ini berbeda dengan hak untuk mengakses atau membuka basis data mysql. Kesalahan 1044 menunjukkan bahwa pengguna telah berhasil teridentifikasi tetapi tidak memiliki hak untuk mengakses database yang diminta. Sementara itu, kesalahan 1045 berhubungan dengan masalah autentikasi, seperti username atau password yang dimasukkan tidak cocok.

**Analisis 4**
- Mode cookie lebih aman karena saat pengguna login, username dan password dimasukkan, sehingga kredensial tidak perlu disimpan langsung di file konfigurasi phpMyAdmin. Dengan cara ini, risiko kredensial yang nampak atau terbaca dari pengaturan bisa diminimalkan.
